# Optional NPC endpoint acceptance

Current evidence is isolated source acceptance only; see [integration and limits](NPC_DIALOGUE_INTEGRATION.md).

Before activation, use an isolated authenticated environment to prove native Account attribution; exact Host/Origin and CSRF; matching run ownership and actual registered dialogue capability; nearby NPC presence; no client authority injection; visible-only context; bounded provider latency and errors; current approved model/output/input policy; privacy/consent; shared/global budgets; quota/cache isolation; logout/revocation/expiry; and no game-state writes. Capture synthetic account labels and bounded statuses, not credentials, prompts containing private data, session values or raw provider errors.

Source CI with synthetic providers and disposable Redis cannot certify live provider availability, live Account acceptance, production policy approval or gameplay release. No route should be mounted and no provider key configured merely to make these fixtures pass.
